# The operator grants the Tool identity's Azure roles, and the tool verifies them

Status: accepted (2026-11-09, [Grilling: Hosting, identity and least-privilege role](https://github.com/mfgAkilae/nsgfw/issues/20)). Amended on 2026-11-09 by [Grilling: Review round on placement, egress posture and MVP shape](https://github.com/mfgAkilae/nsgfw/issues/27): a third, optional role holds the rights for tool-written ASG membership. Amended on 2026-11-10 by [Grilling: Operations: restore, exit, upgrades and exposure](https://github.com/mfgAkilae/nsgfw/issues/29): an Environment's flow-data workspace may lie outside every Environment and then gets a Reader assignment of its own, and the Reader reads log data through a data action limited to one table. Amended on 2026-11-10 by [Grilling: ASG membership of private endpoints and multi-IP network interfaces](https://github.com/mfgAkilae/nsgfw/issues/39): `nsgfw ASG Writer` holds no private endpoint write, because the tool never writes private endpoint membership ([ADR 0006](0006-asg-objects-one-managed-asg-per-vnet.md)). Amended on 2026-11-12 by [Review: Grill review of the complete design package](https://github.com/mfgAkilae/nsgfw/issues/23): a fourth role, `nsgfw Flow Reader`, takes the workspace reads and the data action from `nsgfw Reader`, the Reader gains two reads, and the linked-access test decides the five join actions.

The brief requires a least-privilege custom role for the Tool identity and a documented reason for every permission. One Tool identity serves all Environments ([Grilling: Environment and tenancy model](https://github.com/mfgAkilae/nsgfw/issues/9)). In a Terraform Environment the tool writes nothing to Azure ([ADR 0010](0010-terraform-mode-data-contract-and-azure-observation.md)). Often a different team owns the management group of an Environment than the team that runs the tool. A tool that can assign roles could also widen its own rights.

We decided:

- **Four custom roles, one of them optional.** `nsgfw Reader` holds only the reads the tool needs and is assigned in every Environment, at the Environment's scope. It holds no data action and no action on a Log Analytics workspace, so it stays assignable at a management group. `nsgfw Flow Reader` holds the reads of flow data and is assigned on the flow-data workspace only (see below). `nsgfw Writer` holds only what Managed NSGs need: NSG write, delete and join, subnet write, and `joinNetworkSecurityRule` on ASGs. It is assigned in ARM Environments only, at the Environment's scope or narrower, for example on the subscriptions that hold Zones. `nsgfw ASG Writer` holds what only tool-written ASG membership needs: ASG write and delete, `joinIpConfiguration` and network interface write. It holds no private endpoint write: a write on a private endpoint whose connection was approved automatically also needs the approval right on the linked resource, and the tool carries private endpoints by their IPs instead. An operator who uses no ASG objects never grants it. The full network interface PUT on other teams' VMs is the widest right the tool can hold, and across VNets an ASG becomes a list of IPs anyway ([ADR 0006](0006-asg-objects-one-managed-asg-per-vnet.md)). No role holds Compute writes.
- **Explicit actions only, no wildcards.** Every action is listed one by one with its reason, and the same list drives the tool's permission check. A new action arrives only with a tool version that needs it. An action whose need Microsoft does not document stays out until a test shows that it is needed.
- **Five join actions stay out of the Writer until the linked-access test.** They are the join actions on a route table, a NAT gateway, a service endpoint, a service endpoint policy and a subnet. A subnet or network interface PUT may need them for references it sends again unchanged. The linked-access test decides them: a subnet PUT with route table, NAT gateway and service endpoints, and a network interface PUT with NSG, public IP and load-balancer pool. It is the first integration test of the onboarding increment. Until then the tool maps the error `LinkedAuthorizationFailed` to the missing action and names it.
- **Two reads joined the Reader on 2026-11-12.** `Microsoft.Network/networkGroupMemberships/read` serves the Security layer of Azure Virtual Network Manager. The tool reads the effective security admin rules per VNet through the documented REST call at the full reconcile and at Submit, and Resource Graph stays the fast path for the Drift poll. Where a right is missing, the Security layer shows "cannot read" and not "none". `Microsoft.Insights/eventtypes/values/read` reads the Activity Log caller that the Handover evidence names.
- **One set of role definitions** with one management group as assignable scope, by default the tenant root management group, created by the `instance` Terraform module. The `environment-access` module creates the role assignments of one Environment, and that Environment's owner runs it.
- **The tool never assigns roles.** It holds no `Microsoft.Authorization/roleAssignments/write`.
- **The tool verifies its effective permissions** at Environment onboarding, at Zone onboarding, once a day and before the first write of every Deployment. A missing action flags the Environment or Zone with the actions it lacks and blocks Deployments to the affected Zones before their first write, like Drift, Policy and live limits ([ADR 0022](0022-a-version-exists-from-its-commit-and-deployments-plan-from-the-deployed-state.md)). A missing read stops Drift polling where it applies and is flagged too.
- **The tool reads only inside Environments.** An Address object that stands for an Azure resource (subnet, VNet, External ASG object) must lie in an Environment. A subscription with shared infrastructure, such as a hub, joins an Environment without Zones and gets only the Reader there.
- **The flow-data workspace is always a referenced resource.** `environment-access` takes the resource ID of an Environment's Log Analytics workspace and assigns `nsgfw Flow Reader` on the workspace alone, wherever the workspace lies. It often sits in a management subscription outside every Environment, and it is the only resource the tool reads there. A workspace has no discovery, no Drift and no Coverage, so the reasons against read-only scopes below do not apply to it.
- **Log data through a role of its own, with a table condition.** `nsgfw Flow Reader` holds `Microsoft.OperationalInsights/workspaces/read`, `Microsoft.OperationalInsights/workspaces/query/read` and the data action `Microsoft.OperationalInsights/workspaces/tables/data/read`. Every Flow Reader assignment carries a condition that limits it to the table `NTANetAnalytics` (attribute `Microsoft.OperationalInsights/workspaces/tables:name`). The data action cannot stay in the Reader: Azure does not allow a custom role with `DataActions` at management group scope ([custom roles](https://learn.microsoft.com/en-us/azure/role-based-access-control/custom-roles), retrieved 2026-11-12), and an Environment can be one management group. Granular RBAC is generally available since 2025-11. The legacy table action `workspaces/query/NTANetAnalytics/read` stays out: Microsoft calls it no longer recommended, and in a workspace in `DataActionsOnly` mode only data actions give access to log data ([granular RBAC](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/granular-rbac-log-analytics), page date 2025-11-18; [manage access](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/manage-access), page date 2026-09-21; both retrieved 2026-11-10).

## Considered Options

- **One custom role.** Rejected. Terraform Environments would hold write rights, or need a second definition after all.
- **The tool assigns its own roles** through User Access Administrator with a condition. Rejected. It is a privilege-escalation surface.
- **Wildcards for reads,** such as `Microsoft.Network/*/read`. Rejected. Microsoft advises explicit actions, because wildcards include future actions automatically.
- **Role definitions per Environment.** Rejected. Every Environment would need a new apply on each upgrade, and the definitions could drift apart.
- **Read-only scopes outside Environments.** Rejected. It would add a concept with its own discovery, Drift observation and read filter for Roles.
- **The management subscription joins an Environment without Zones for its workspace.** Rejected on 2026-11-10. The Reader would read every VNet and NSG there, and with Environments defined by management group, the subscription would need an Environment of its own.
- **`nsgfw Reader` with the data action, assigned per subscription** where a management group defines the Environment. Rejected on 2026-11-12. A new subscription under the management group would not join the Environment on its own.
- **The legacy table action, alone or next to the data action.** Rejected on 2026-11-10. Alone it fails in `DataActionsOnly` workspaces; next to the data action it adds an action that nothing needs.
- **The approval right for automatically approved private endpoints,** `<provider>/<type>/privateEndpointConnectionsApproval/action` on each linked resource, which an ASG-only write on such an endpoint needs ([Task: Empirical check of subnet NSG swaps and private endpoint ASG writes](https://github.com/mfgAkilae/nsgfw/issues/33), T9). Rejected on 2026-11-10. It sits on resources of other teams, often outside every Environment, one action per target service; Microsoft documents it only as what approves new connections; and with it the tool could approve new private endpoints to those resources, a path to their data that a firewall tool must not hold.
- **Adding every candidate join action at once.** Rejected. Together with subnet write, they would let the identity attach any route table or NAT gateway to a subnet.

## Consequences

- Whoever applies the `instance` module needs the right to create role definitions at the chosen management group.
- After an upgrade that needs a new action, the permission check flags it until the role definitions are updated.
- An Environment owner who narrows the Writer also limits which subnets can become Zones. Zone onboarding then fails and names the missing actions.
