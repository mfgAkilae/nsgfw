Does the order of writes still matter?

Prototype for Prototype: Translation engine worked examples, first check, under ADR 0016 (deny Rules on both sides, Egress posture per Zone).

Question. A Deployment writes Managed NSGs one after another. While it runs, some Zones hold the old content and some hold the new one. Does any such mix allow only flows that the old or the new Version allows, whatever the order of writes? If so, ADR 0009 (Tighten and Loosen phases, interim contents, holds) can be replaced.

The argument to check (destination dominance). A flow from Zone A to Zone B passes A's outbound and B's inbound NSG rules. Suppose that in every Version, B's inbound NSG rules deny each flow that A's outbound NSG rules deny. Take any mix with A's NSG at Version v and B's at Version w. If the mix allows the flow, B's inbound at w allows it, so A's outbound at w allows it too, and Version w allows the flow. A flow with a non-Zone endpoint passes one Managed NSG, and one PUT changes that NSG as a whole. The argument works for any number of Versions in flight.

What the model contains. Three Zones (A and B in IPv4, C in IPv6 and so outside the default Internal address space), an on-premises host, an Internet host, two ports, an ASG object, the service tags VirtualNetwork and Internet, both Egress postures, Inherited defaults, the Intra-zone default, own-side pruning, and ADR 0016's rule that destination-enforced Zones leave out outbound NSG rules that have no effect.
